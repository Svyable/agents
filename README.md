## A profile that can lead to work

A conventional profile ends with a list of links. This one should help a person—or an agent acting for one—make a good next decision.

- **Understand the person.** Connect the builder, author, and musician without flattening them into a keyword list.
- **Inspect the work.** Follow public repositories, released books, source material, and clearly labeled project states.
- **Find a useful contribution.** Start with an invitation and the target repository’s instructions.
- **Bring a concrete proposal.** Name the outcome, deliverable, evidence, acceptance criteria, budget, and accountable principal.
- **Agree before transacting.** Discovery is public. Commercial scope, spending, contracts, and representation require explicit agreement.

The [Pages site](https://svyable.github.io/agents/) makes those paths visible. Its agent view reveals a contribution route for every project. The collaboration packet builder prepares a readable brief and downloadable JSON, then lets the visitor review and submit through GitHub. It does not pretend a static website is an autonomous trading counterparty.

## For agents: discover → inspect → propose → contribute

1. Read **[AGENTS.md](AGENTS.md)** for repository scope and authority boundaries.
2. Load **[agent-index.json](docs/agent-index.json)** and **[llms.txt](llms.txt)** for identity, project routes, sources, and interaction details.
3. Choose an **[open invitation](invitations/)** and inspect current Issues/PRs to avoid duplicate work.
4. Read the target repository’s `AGENTS.md` and any required skills.
5. Submit a bounded, evidence-bearing PR in that target repository. Link the result back to the invitation when appropriate.

The existing invitations remain available: [Desk prose](invitations/desk-anti-slop-pass.md), [Frontier Lab experiments](invitations/frontier-simple-10x.md), [ProofBot statements](invitations/proofbot-erdos-lock.md), and [screenplay adaptation](invitations/screenplay-adapt.md). Access and release rules remain those of the target.

For a new connection, [open a collaboration proposal](https://github.com/Svyable/agents/issues/new/choose). For a code commission, use [Agent for Hire’s own intake](https://github.com/Svyable/agent-for-hire). An inquiry is not an accepted order.

## Agent search optimization, with evidence

The implementation provides semantic, statically rendered HTML; stable canonical identity; Schema.org `Person`, `ProfilePage`, and `ItemList` markup; source-linked biography; a dated project registry; `llms.txt`; a sitemap; and a custom agent manifest. Humans and machine readers encounter the same facts.

These are inspectable discovery surfaces, not a promise of ranking or indexing. The manifest is **not** a live A2A/MCP service, payment API, identity credential, or delegated authority token. The project-scoped `docs/robots.txt` is advisory; effective crawler policy belongs at the GitHub Pages origin root.

## Maintain and publish

The Pages source is **`docs/`**. No application dependencies or build service are required to serve the committed site.

```bash
python3 scripts/build.py
python3 scripts/validate.py
node --check docs/app.js
```

Edit `docs/data/profile.json`, `docs/data/projects.json`, `templates/index.html`, `docs/style.css`, and `docs/app.js`; regenerate before committing. `docs/index.html` and discovery files are generated. Keep the README and `docs/sources.html` aligned with substantive profile changes.

The included workflow validates the site and deploys `docs/` with GitHub Pages. **One-time repository setup:** Settings → Pages → Source → **GitHub Actions**. If Pages has not been enabled, a repository administrator must select that source; a workflow’s ordinary `GITHUB_TOKEN` cannot enable a new Pages site. Alternatively, publish `main` / `/docs` via branch deployment and remove the custom deployment workflow to avoid conflicting deployment sources.

The intended public address is **https://svyable.github.io/agents/**. Inspect the latest [deployment run](https://github.com/Svyable/agents/actions) to confirm publication.
